The entities involved in a hit, handed to damage mitigation and defense penetration functions that depend on more than the stat values: a formula whose constant grows with the attacker's level, or one driven by another stat of the attacker or the target.

public readonly struct ReductionContext

Remarks

It carries references and derives what it exposes only when asked, so a function that needs nothing from it (flat, percentage, logarithmic) costs nothing. Future inputs are added as properties here, not as new parameters on the functions.

Entity-backed or value-backed. The damage pipeline builds an entity-backed context. Tools and tests that have no entities can state levels directly with ReductionContext(int, int), and the full constructor lets an explicit level take precedence over the entity's. default is a valid context: no entities, target level 1, no performer (the same as Default).

Contract for functions. The context is valid only during the call: do not store it or its references. Functions are pure, so treat the entities as read-only even though they are reachable. Read a stat with TryGet on TargetStats / PerformerStats and treat a missing stat as 0: those readers are null when the context was built from levels alone.

What is not a stat. TargetStats and PerformerStats exist to read stats the way the pipeline does: the attacker's through the ownership fallback chain, which an entity cannot derive on its own (hence the reader the pipeline injects for it; the target has no chain and is read directly). Anything else is reached through Target and Performer. The target's maximum health, for example, is not a stat but EntityHealth.MaxHp: context.Target.GetEntityHealth() returns it, or null when the context has no target entity or the target has no health component.

It is a readonly struct passed by in: building and passing it does not allocate, which matters on the per-hit damage path.
